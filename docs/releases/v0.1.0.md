# ActionTape v0.1.0 — source preview

ActionTape brings a native recording and debugging workflow to macOS
Accessibility automation. Record supported clicks across apps you select, edit
the resulting semantic steps, and replay with an ordered trace. The same YAML
tape runs from Studio or the `actiontape` CLI.

## Included in this preview

- A SwiftUI Studio with a searchable local tape library, editable actions and
  locators, step duplication/reordering, YAML import/export, and live run status.
- Read-only **Inspect matches** diagnostics with ranked candidate details,
  scoring explanations, and unique/missing/ambiguous outcomes.
- Selected-app click recording with a floating Stop control. Recording captures
  application activation and supported `AXPress` controls; text fields and
  keyboard input are excluded.
- Seven typed actions: activate app, press, set value, hotkey, wait, assert, and
  pause. Variables, explicit retries, bounded timeouts, and cancellation are
  shared between Studio and the CLI.
- Run-time variable prompts in Studio, including secret inputs with no default
  created by the variable editor. The CLI can read values from existing
  environment variables.
- Semantic targeting with explicit-field constraints, ambiguity failure, and
  application-scoped execution. Coordinate fallback is disabled by default.
- A CLI for validation, dry-run, permission diagnosis, point inspection,
  replay, and value-redacted JSON trace export.
- ActionTape Practice: an included native test app whose synthetic label
  workflow changes only in-memory state.
- Vendored Yams/libyaml, offline build/test checks, and local app packaging
  scripts with resource, icon, metadata, and license verification.

## First run

Use macOS 14+ with a compatible Swift 6 toolchain. From a source checkout:

```bash
swift build
swift test
bash scripts/package-practice-app.sh
open 'dist/ActionTape Practice.app'
swift run actiontape validate examples/practice-label.yaml
swift run actiontape run examples/practice-label.yaml --dry-run
swift run actiontape doctor
```

After Accessibility access is granted to the command-line executable or its
terminal host:

```bash
swift run actiontape run examples/practice-label.yaml \
  --trace .build/practice-trace.json
bash scripts/package-app.sh
open .build/artifacts/ActionTape.app
```

Studio needs its own Accessibility grant. Follow the
[Studio guide](../studio-guide.md) for editing and recording.

## Distribution and compatibility

This is a **source preview**, not a signed binary release. The scripts build
development apps for the host architecture. They do not add a Developer ID
signature or notarization, and they do not create a universal binary.

Format version `1` is the current tape format. Before 1.0, schema and trace
changes may require updates to tapes or consuming tools; keep original tapes
when upgrading and review the changelog. Unknown fields, duplicate fields,
unsupported format versions, YAML anchors/aliases/tags, and oversized input are
rejected rather than silently interpreted. This preview does not promise a
stable external trace API.

Playback requires an interactive logged-in macOS session. App support depends
on the Accessibility tree the app exposes. Practice is the recommended first
target; Finder, TextEdit, and Notes examples are format demonstrations that can
depend on language, app version, account, and initial window state. Automated
checks cover builds, tests, format validation, and bundle assembly; they do not establish a
broad third-party application compatibility matrix.

See [verification notes](../verification.md) for the tested local environment,
live Practice checks, and the limits of that evidence.

## Known limitations

- Recording does not capture typing, dragging, scrolling, or arbitrary mouse
  gestures. Add text and hotkeys manually.
- Custom controls may lack useful Accessibility identifiers or supported
  actions. Ambiguity needs a more specific locator.
- Traces show status, attempts, timing, and diagnostics, without screenshots or
  Accessibility-tree diffs.
- Secret marking does not encrypt a YAML tape. Imported files may contain
  plaintext defaults. Traces omit input values but can still contain private
  application names or UI labels.
- Cancellation is cooperative. It stops subsequent work and cannot undo an
  action the target app has already performed.

The [roadmap](../../ROADMAP.md) covers broader recording, richer assertions,
locator repair, and signed distribution. Compatibility reports with synthetic
inputs and sanitized traces are especially useful.
